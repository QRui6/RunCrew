# M8-A1.1 产品界面收敛

## 1. 为什么继续调整

M8-A1 第一版虽然建立了统一视觉令牌和产品导航，但仍把活动、聊天、Agent 流程、证据策略和训练运营同时展示在首屏。永久三栏、巨型欢迎标题、英文工程标签和大量状态卡片互相争抢注意力，结果仍然更接近“展示系统具备多少技术能力”的 Demo，而不是围绕用户主任务设计的正式产品。

本阶段不再增加视觉元素，而是通过信息架构删减，把普通用户的唯一主任务重新确定为：选择一次跑步，然后自然提问。

## 2. 用户可感知的变化

- 默认布局从三栏改为两栏，只保留训练记录和对话主区；
- 活动快照、智能体协作、上下文用量和安全边界移入“运行详情”抽屉，用户需要时再查看；
- 删除欢迎页中的 Evidence/Review/Response 流程图、超大宣传标题和英文运行状态；
- 欢迎页改为当前活动名称、简短说明、四个高频问题和一条证据说明；
- 顶部导航改为“对话 / 训练计划 / 开发者”，移除 Private Beta 等演示标签；
- 主标题直接显示当前活动，副标题显示距离、时长、配速和来源，不再重复“活动解读”等系统话术；
- DeepSeek 开关在界面中改称“增强回答”，模型边界仍保持不变；
- Coach、Execution Agent 等工程语言在普通产品面改为联合评估、训练执行、恢复评估和计划调整；
- 训练计划仍保留完整的身体反馈、跨职责评估、人工审核和运行恢复能力。

## 3. 修改文件

- `src/runcrew/web/static/chat.html`：重建两栏产品结构、精简欢迎页，增加按需运行详情抽屉；
- `src/runcrew/web/static/chat.css`：重写布局与组件密度，右侧检查器从永久栏改为覆盖抽屉；
- `src/runcrew/web/static/chat.js`：增加运行详情开关、动态活动标题与精简欢迎状态；
- `tests/test_chat.py`：更新产品入口契约；
- `tests/test_training_operations.py`：验证运行详情、智能体协作和默认隐藏结构；
- `docs/CURRENT_STATE.md`、`docs/ROADMAP.md`、`docs/PROGRESS.md`、`CHANGELOG.md`：同步阶段状态。

## 4. 产品判断

### 正式产品不等于把所有能力都放在首页

多 Agent、Skill、Harness、Trace 和安全边界仍然是项目技术亮点，但它们不应同时成为普通用户的一级导航信息。首页只负责完成“选择活动 → 提问 → 阅读回答”；技术过程通过“运行详情”和“开发者”入口逐层展开。

### 默认简洁，按需解释

训练记录和历史会话常驻，因为它们直接决定当前任务；智能体执行状态属于诊断信息，默认隐藏；计划审核属于独立工作流，通过训练计划抽屉进入。这形成了主任务、辅助任务、工程诊断三个清晰层级。

### 统一用户语言

普通产品面优先使用中文业务概念。模型名、Agent 英文职责和底层 hash 只在确有辨识价值时出现，避免为了体现技术而让用户承担理解成本。

## 6. 已知限制

- 本次应用内浏览器仍没有可用实例，因此没有声称完成截图或逐像素验收；
- 是否达到用户期望的正式产品感，需要用户在本机打开后完成最后一轮主观验收；
- 当前正式感仅覆盖本地单用户产品面，不代表账号体系、多租户、云部署、监控告警和运维能力已经完成；
- 运行详情目前在开始与完成时更新，不是服务端流式 Trace。

## 7. 下一阶段唯一入口

用户先在本机复核收敛后的首屏。如果信息层级通过，则进入 M8-A2，制作系统架构图、训练闭环时序图和无私人数据演示脚本；如果仍有视觉问题，只允许做字体、间距、色彩和组件细节调整，不再扩大首页信息范围。

## 8. 数据与外部额度

本阶段没有调用 COROS、DeepSeek 或其他外部服务，没有读取或提交私人活动明细；测试只使用合成数据和临时 SQLite。
