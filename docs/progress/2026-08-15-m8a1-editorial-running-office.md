# M8-A1.3 运动编辑部式个人跑步办公室

## 1. 本阶段目标

M8-A1.2 已经解决高饱和颜色和旧静态资源缓存问题，但界面仍由通用 SaaS 的侧栏、标题、卡片、标签和抽屉组成，缺少只属于 RunCrew 的产品识别。本阶段不增加业务功能，重新建立“运动编辑部 × 数据实验室”的视觉母题，使用户首先感受到一份正在被阅读的个人训练档案，而不是一个用来展示 Agent 名词的后台。

## 2. 用户可感知的结果

- 品牌区从通用圆角图标改为克制的圆形 `RC` 刊头，并统一使用“个人跑步办公室”产品定位；
- 左侧从后台式记录列表改为“训练索引”，活动项以日期、距离、配速和训练来源形成简洁目录；
- 当前活动以 `RUN 编号 + 日期 + Provider` 组织，活动名称使用编辑式衬线标题；
- 距离、用时、平均配速和平均心率进入连续数据带，不再拆成四张指标卡；
- 增加低干扰的跑步节奏视觉母题，但不把装饰线伪装成真实配速曲线；
- 欢迎区改为研究笔记式提问入口，四个高频问题以编号目录呈现；
- 用户问题和 RunCrew 回答改为双栏标注的训练笔记，不再使用聊天气泡；
- 回答类型、证据引用、置信度和缺失数据改为脚注式元信息；
- 原“运行详情”改为“回答依据”，活动快照、Agent 协作、安全边界和本轮用量仍按需展开；
- 训练运营、身体反馈、Coach 运行、用户批准和 stale 防护保持原有功能与接口。

## 3. 修改文件

- `src/runcrew/web/static/chat.html`：重建刊头、训练索引、活动标题、连续数据带、研究笔记式欢迎区和回答依据入口；
- `src/runcrew/web/static/chat.css`：完整重写产品视觉系统、信息密度、消息排版、抽屉与移动端布局；
- `src/runcrew/web/static/chat.js`：增加活动刊号与关键指标渲染，改造欢迎页和消息语义，保持原 API 与安全 DOM 写入方式；
- `tests/test_chat.py`、`tests/test_training_operations.py`：更新产品名称、静态产品契约并验证新视觉结构和资源版本；
- `docs/CURRENT_STATE.md`、`docs/ROADMAP.md`、`docs/PROGRESS.md`、`CHANGELOG.md`：同步阶段事实。

## 4. 关键策略

### 4.1 视觉母题来自业务，而不是装饰风格

RunCrew 的核心不是“AI 聊天”，而是持续阅读个人训练记录。因此界面借用编辑部的刊号、索引、正文、脚注和档案结构，再用数据实验室的指标带和证据编号补充可信度。这样即使隐藏所有 Agent 工程信息，页面仍能表达这是一个跑步训练产品。

### 4.2 默认阅读结论，按需检查过程

主界面只保留当前跑步、关键指标、问题、回答和输入。Agent 节点、上下文用量与安全规则继续存在，但放在“查看依据”抽屉中；训练计划写入仍在独立的“训练运营”抽屉中完成。

### 4.3 不伪造数据可视化

当前聊天活动 DTO 没有逐圈数组，因此数据带末端只使用明确的品牌节奏装饰，不把它标注为真实配速曲线。真正的分圈图必须等后端提供受 Schema 约束的数据后再实现。

### 4.4 不用 UI 重构绕过既有安全边界

页面仍只用 `textContent` 构建服务端内容，不增加 `innerHTML`；DeepSeek 仍需用户显式开启；计划变更仍由服务端重放和 revision 状态机审核，浏览器不能提交 patch。

## 5. 实施中发现的问题与处理

- 原测试固定断言旧产品名和 `v=20260815-3`，资源升级后回归测试准确暴露了契约变化；处理方式是把测试更新为“个人跑步办公室”和 `v=20260815-4`，并增加训练索引、连续数据带、回答依据和动态活动标题的结构断言；
- 对话标题原先会覆盖当前活动标题，容易让活动档案失去稳定视觉锚点；本阶段改为始终保留当前活动名称，会话标题只在左侧对话索引中展示；
- 为避免在没有逐圈数据时制造“漂亮但虚假”的曲线，最终没有把概念稿中的曲线作为数据图实现。

## 7. 已知限制与下一阶段唯一入口

- 本阶段完成代码、DOM 契约和响应式规则，没有声称完成真实浏览器逐像素验收；
- 中文衬线字体使用系统字体栈，不同 Windows 环境会有轻微字形差异；
- 装饰节奏线不是逐圈数据图；真正图表需要后端增加受约束的 lap 摘要字段；
- 下一步由用户在本机打开最新页面，重点复核桌面首屏、对话产生后的长回答和“查看依据/训练运营”两个抽屉；视觉方向确认后进入 M8-A2 演示脚本和架构图。

## 8. 数据与外部额度

本阶段没有读取真实私人活动明细，没有调用 COROS、DeepSeek 或其他外部服务，也没有产生模型费用。自动化测试继续使用合成数据和临时 SQLite。
