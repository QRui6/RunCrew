## 5. 场景解释边界

9个场景使用真实 DeepSeek Policy，包括3个正常任务、3个工具韧性场景、确认门和2个预算场景。`unknown_tool_blocked`、`tampered_arguments_blocked`、`premature_finish_blocked` 使用脚本化 Policy 注入非法动作，因此它们证明 Harness 能阻止危险动作，不代表 DeepSeek 自身一定不会产生这些动作。

## 6. 模型与架构决策

- 不升级 `deepseek-v4-pro`：Flash 已达到当前动作协议的全部正确性门槛；
- 不拆多 Agent：没有观察到职责冲突、上下文超载或工具权限无法由单 Agent 管理；
- 保留确定性 Skill：模型只选择动作，不接管配速、负荷、阈值或 evidence 计算；
- 保留 Harness 最终执行权：参数、权限、预算、确认、重试、超时和输出 Schema 继续由本地代码校验。

## 7. 真实工程问题与价值

评测共经历三次完整运行：第一次通过但 CLI 隐式改写超时导致 Hash 漂移；第二次 Hash 一致但暴露 v1.0 的1秒预算只适合离线 Policy；第三次使用正式 v1.1 公平预算完成同题对照。项目没有隐藏失败，而是保留报告、升级 Suite 版本、增加回归测试和 ADR。

这比一次成功演示更能体现 Evaluation、Harness、Loop 和上下文工程能力。

## 8. 面试表达

> 我先用确定性 Policy 建立12场景 Agent 基线，再让 DeepSeek 只替换动作选择层。真实评测中我发现命令对模型放宽超时会改变 Suite Hash，而原始1秒离线预算又无法公平评估网络模型，所以把 Suite 升级到 v1.1，让两种 Policy 使用相同15秒预算。最终双方同 Hash 12/12，DeepSeek 无动作解析错误、无越权工具执行，费用约0.00076美元。评测没有证明需要多 Agent，因此我保留单 Agent，并把复杂度投入在 Harness、Trace、预算和可回放证据上。
