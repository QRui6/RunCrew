# RunCrew 求职材料包

这组材料把项目代码压缩成简历和面试可以使用的叙事，同时保留证据边界。推荐按下面顺序使用：

1. [简历条目](resume-entry.md)：选择三行版或展开版，不要把两版同时放进简历；
2. [核心难点与讲述框架](core-challenges.md)：面试时按问题、约束、方案、验证、边界讲清技术决策；
3. [证据映射](evidence-map.md)：提交简历前核对每个数字和结论；
4. [面试追问](interview-questions.md)：逐题练习，不背框架名词，回答要能落到代码和失败案例；
5. [五分钟现场演示](../demo/five-minute-demo-script.md)：需要打开项目时按固定顺序操作。

## 当前推荐定位

RunCrew 适合被描述为“基于真实运动数据的可审计多智能体训练运营系统”，核心价值不是聊天界面，也不是 Agent 数量，而是：

- 把计划、执行、恢复反馈和调整接成有状态闭环；
- 把数据事实、确定性判断、LLM 表达和人工确认分开；
- 按 Agent 职责裁剪记忆字段与预算，并保留完整选择审计；
- 用权限、Schema、Hash、revision、重放和版本化评测让 Agent 行为可验证。

## 使用原则

- `195 passed` 是自动化回归结果，不是模型准确率；
- `12/12` 是单 Agent 在同 Hash 合成套件上的确定性 Policy 与真实 DeepSeek 对照；
- `18/18` 是确定性 Coach Policy 的多 Agent Harness 基线，不是真实 LLM 多 Agent 结果；
- `16/16` 是确定性 Memory Manager 合成基线，分母不是16个真实用户；
- 合成评测和演示不能表述为用户增长、训练提升或生产稳定性；
- 聊天路径的真实 DeepSeek 8轮同题评测尚未完成，不能与 Review Agent 的真实模型结果混为一谈。
