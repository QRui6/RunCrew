# ADR-0012：聊天自由度采用分层论断，而不是全句强制引用

- 状态：接受
- 日期：2026-08-09

## 背景

M6-A2 要求模型输出 `answer + evidence_refs`。它能阻止无依据的个人数据结论，但也容易把通用跑步知识、假设讨论和训练建议强行压缩成三类 finding 的复述，形成“有依据但很死板”的聊天体验。

## 决策

- 自然语言正文保持自由，不要求每句话逐条引用；
- 回答声明五种模式：个人数据分析、数据与训练思路混合、通用知识、澄清、安全转向；
- 关键论断分为 `observed_fact`、`data_inference`、`general_knowledge`、`coaching_suggestion`；
- 只有关于用户个人的事实与推断必须引用 Training Review evidence；
- 通用知识和建议可以没有个人 evidence，但不能表述成已经发生的用户事实；
- 数据不足时允许询问澄清问题；疼痛问题允许一般风险提示但不允许诊断；
- 用版本化多轮评测分别衡量 grounding、openness、safety 和 context，而不是只统计 Schema 通过率。

## 原因

- “事实严格”和“表达自由”不是二选一，可以在论断层分离；
- 结构化论断让 Harness/评测检查关键事实，正文仍能自然解释和讨论；
- 通用知识不需要伪造个人引用，避免形式主义 evidence；
- 回答模式与论断类型可以在 UI 中透明展示，方便用户理解依据边界。

## 后果

- `ChatAnswer` 契约比 M6-A2 更丰富，旧消息通过 evidence 自动生成兼容论断；
- 模型 Prompt 和评测必须同时理解五种模式、四类论断；
- Schema 只能校验引用结构，仍需要真实模型多轮评测判断内容质量；
- 未来增加新 Skill 时，应扩展可引用 evidence 类型，不应让 LLM 自行创建来源。

## 替代方案

- 所有句子强制 evidence：拒绝，因为会让通用知识和建议机械化；
- 完全取消 evidence：拒绝，因为个人数据结论会失去可审计性；
- 只在 UI 加免责声明：拒绝，因为不能约束模型输出结构；
- 为每种问题拆一个 Agent：暂不采用，因为当前单 Policy 加分层契约可以满足职责。
