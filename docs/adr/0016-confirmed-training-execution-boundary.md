# ADR-0016：训练执行候选与用户确认边界

状态：接受
日期：2026-08-13

## 背景

计划课和实际 Activity 之间没有天然主键。仅凭日期与距离自动写入可能误认多设备重复活动、临时换课或同日多次跑步；把缺少活动直接判为跳过也会把同步失败误当成用户行为。

## 决策

1. 执行对照先生成只读候选，不自动修改计划；
2. `unmatched` 与 `skipped` 分离，跳过只来自用户显式确认；
3. 清晰候选标记 `suggested`，候选竞争标记 `ambiguous`；
4. 用户确认、跳过或清除执行状态时必须提交 `base_revision`；
5. 写入后提升计划 revision，并新增不可变的执行确认审计记录；
6. 同一计划内一条活动只能关联一节课，未来课和相差超过三天的活动拒绝确认。

## 原因

- 把概率性匹配和事实写入分开；
- 对同步缺失、候选冲突和人工纠正提供明确语义；
- 保持 Agent 建议权、用户决定权和数据库审计链；
- 为后续 Coach Orchestrator 提供可信的计划执行反馈。

## 后果

- 用户需要多一次确认操作；
- v1 不解析标题、配速区间或分段结构，某些训练需要人工选择；
- plan revision 同时保护计划内容和执行状态，任何旧提案都将按现有规则失效。

## 替代方案

- 自动写入最高分候选：交互更少，但错误关联会污染后续恢复和计划判断；
- 没活动即标记跳过：无法区分未同步和真实未训练；
- 不保存审计记录：实现简单，但无法解释谁在何时改变了执行事实。
