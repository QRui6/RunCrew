# ADR-0025：Memory Manager 使用版本化合成场景评测真实服务边界

## 状态

接受

## 背景

M9-A 至 M9-D 已建立类型化长期偏好、周训练记忆、按职责 Context 和聊天待确认候选，但分散的单元测试不能直接回答“候选是否会误写”“过期或篡改能否阻断”“不相关记忆是否会污染 Agent Context”等整体问题。若只汇报测试全通过，也无法让后续规则、模型抽取或检索实现进行同题比较。

## 决策

1. 建立 `memory-manager-eval/1.0`，用16个不含私人数据的版本化场景覆盖 candidate、lifecycle、integrity、retrieval 四类行为。
2. Candidate 场景固定明确高/中置信表达，以及临时、否定、多星期歧义和业务不支持表达；Suite 同时保存输入和期望，任何变化都会改变 Suite Hash。
3. 生命周期与完整性场景不使用测试替身模拟结果，而是在隔离的 SQLite 中运行正式 Repository、候选服务、正式偏好服务和来源重放校验。
4. 职责召回与无关记忆注入直接运行正式 Memory Context Builder，比较实际选择、排除原因、字段最小化、Context Hash 与 Audit Hash。
5. 报告聚合候选召回、负样本拒绝、生命周期、来源完整性、人工确认边界、职责隔离、无关注入抵抗、Schema 和意外正式写入指标；基线要求16个场景全部满足期望且意外写入为0。
6. 用例、Suite/Report Schema 可以进入 Git；运行报告只能写入 `data/private/`。
7. 这套合成基线只证明已列场景的工程行为，不等于真实用户表达准确率。未来模型抽取必须使用相同公开输入和期望对照，不能用新的宽松题集替代。

## 原因

- 复用真实服务可以发现状态机、事务、来源和 Context 之间的组合回归；
- Suite Hash 把“实现变好”与“题目被改简单”分开；
- 将意外正式写入单独计数，避免平均指标掩盖高风险副作用；
- 结构化检索在职责隔离与无关注入场景中已可确定性解释，目前没有证据支持引入向量数据库。

## 后果

- `runcrew eval memory` 可以离线生成可比较报告，不读取真实数据库、不调用 COROS 或 DeepSeek；
- 当前16/16只是确定性合成基线，复杂隐含、跨消息表达和真实自然语言分布仍未评测；
- 后续修改提取规则、生命周期或 Context Policy 时，必须原样复跑 v1.0；若业务期望确需变化，应升级 Suite 版本并保留旧报告语义；
- 只有结构化检索在新增真实场景中出现可测瓶颈，才进入向量检索 ADR。

## 替代方案

### 只依赖现有单元测试数量

能防局部回归，但缺少统一题集、Hash、聚合指标和跨实现对照，拒绝。

### 直接使用真实聊天数据评测

更接近用户分布，但会把私人文本带入可提交用例，也没有稳定 ground truth；先使用公开合成基线，真实数据只能在本地匿名评审流程中补充。

### 立即引入 LLM Judge 或向量数据库

当前输出都是类型化状态和确定性选择，可以直接判分；引入概率 Judge 或新检索组件只会增加不可解释变量，拒绝。
