# ADR-0010：评测使用统一且现实的时间预算

- 状态：接受
- 日期：2026-08-09

## 背景

`review-agent-eval/1.0` 最初只用于确定性离线 Policy，默认 Agent 总超时为1秒。接入 DeepSeek 后，第一次完整命令把模型场景临时改成60秒，虽然12/12通过，却改变了 Suite Hash。删除改写后，第二次报告与基线 Hash 相同，但9个网络模型场景都在1秒内超时；此前成功请求的单次或双次网络往返通常需要1.7至4.7秒。

这说明“相同1秒预算”形式上公平、实际上只测出了网络存在，而“只给模型放宽预算”又破坏了同题比较。

## 决策

- Suite 升级为 `review-agent-eval/1.1`；
- 所有 Policy 使用相同的15秒 Agent 总运行预算；
- 时间预算继续作为 Suite 内容参与 Hash，不建立隐藏的模型专属覆盖；
- 工具故障注入仍使用独立的短 `tool_timeout_seconds`，不会因总预算放宽而失效；
- 延迟通过端到端 P95 和模型耗时单独比较，不用不现实的1秒门槛替代性能指标；
- 总超时取消正在进行的模型请求时，记录已发起的 API 尝试；没有响应 usage 时 Token 与费用保持未知来源的0值，并明确不能据此推断供应商未计费。

## 原因

- 同一 Suite、同一 Hash、同一预算才能形成可审计对照；
- 15秒覆盖目前观察到的 DeepSeek 正常延迟，同时保留明确的失控停止边界；
- 版本升级明确表示评测条件发生变化，避免用相同版本名覆盖历史基线；
- 把延迟作为独立指标，可以同时比较正确性与性能，而不是让网络开销吞掉全部质量信号。

## 后果

- v1.0 的确定性基线、60秒第一次报告和1秒第二次报告继续作为历史审计材料；
- v1.1 必须重新生成确定性基线和 DeepSeek 报告；
- 两份 v1.1 报告的 Suite Hash 必须相同，才能形成正式比较；
- 15秒是当前评测预算，不代表产品 SLO，未来修改必须再次升级 Suite 版本。

## 替代方案

- 从 Hash 中排除时间预算：拒绝，因为会让不同执行条件伪装成同一题集；
- 保持1秒预算：拒绝，因为只能测量网络延迟，无法评估模型动作质量；
- 只为 DeepSeek 放宽预算：拒绝，因为这正是第一次 Hash 漂移的根因；
- 完全取消总超时：拒绝，因为会失去 Harness 的有界运行保证。
