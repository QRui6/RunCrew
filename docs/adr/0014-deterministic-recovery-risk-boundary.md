# ADR-0014：恢复 Agent 只能解释确定性风险结果，不能自行诊断或打分

## 状态

接受。

## 背景

M7 需要增加恢复与风险职责，但训练风险同时涉及主观反馈、训练量、课表和医疗安全红旗。如果直接让 LLM 根据自由文本给出“今天能不能跑”，模型可能忽略数据缺失、改变阈值或输出诊断性结论，也无法稳定回放。

## 决策

- 先实现 `assess-running-recovery` 确定性 Skill，再创建 Recovery Agent；
- 输入只包含 RunCrew 内部目标 ID、带时区评估时间、可选 Provider 和回看窗口；
- Context 只读取评估时间之前的规范化活动和反馈，防止未来数据泄漏；
- 急性症状使用枚举字段，不从自由文本猜测；
- recommendation 固定为 `proceed / reduce / rest / seek_professional_help / insufficient_data`；
- 心肺红旗优先级高于训练量和一般恢复指标；
- 疲劳、睡眠、疼痛和训练量阈值标记为 RunCrew 保守工程规则，不冒充医学标准；
- Skill 不直接修改计划，只输出 `plan_action`，后续仍需计划 Agent 形成提案和用户确认；
- LLM 以后只能解释已经通过 Schema 校验的结果，不能重新计算等级。

## 原因

把风险分层放在确定性 Service 中，可以版本化规则、生成稳定 Hash、注入缺数和红旗场景并审核每条 evidence。将写入动作继续放在 M7-A 的提案—确认边界内，则 Recovery Agent 没有越权修改正式课表的能力。

## 后果

- 每次阈值变更必须升级 `ruleset_version` 并更新评测；
- `proceed` 只表示未触发当前规则，不是医学许可或安全保证；
- 缺少近期反馈时返回数据不足，不能默认正常训练；
- 多来源活动可能重复时调用方应指定 Provider；
- 后续需要为 Recovery Agent 增加工具白名单、Trace、预算和跨 Agent 提案协议。

## 替代方案

1. **让 LLM 阅读全部数据后自由判断**：自然但不可回放，且医疗边界不稳定，拒绝。
2. **只用训练负荷判断恢复**：忽略用户主观疼痛与急性症状，拒绝。
3. **恢复 Agent 直接修改课表**：违反 M7-A 用户确认边界，拒绝。
4. **直接构建医疗伤病 Agent**：数据和资质不支持，超出项目范围，拒绝。
