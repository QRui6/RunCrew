# RunCrew 5分钟求职演示脚本

## 演示前30秒：重置环境

```powershell
cd D:\AgentProjets\RunCrew
.\.venv\Scripts\runcrew.exe demo-seed --reset
.\.venv\Scripts\runcrew.exe demo --db data\private\demo\runcrew-demo.db
```

确认终端输出包含：

- `synthetic_data: true`；
- `activity_count: 8`；
- 数据库路径位于 `data/private/demo/`。

不要配置 DeepSeek Key，不要使用真实 `data/runcrew.db`。

## 0:00—0:45：问题和产品入口

操作：打开首页，选择“晨间轻松跑 · 演示数据”。

讲解：

> RunCrew 解决的不是记录轨迹，而是把计划、实际执行、身体反馈和调整连接成可审计闭环。演示数据完全合成，产品服务只绑定本机。

## 0:45—1:45：连续对话与证据

操作：点击“这次跑得怎么样？”，等待离线回答，再追问“这个判断用了哪些证据？”。打开“回答依据”。

讲解：

> 首轮会真实运行 Review Agent Harness，确定性 Skill 生成复盘和 evidence；后续追问复用不可变快照，只带最近8条消息。个人事实必须引用 evidence，LLM 不负责计算指标。

应看到：活动摘要、证据引用、置信度、缺失数据和运行 Trace。没有模型 Key 时仍能完成演示。

## 1:45—2:40：训练执行闭环

操作：打开“训练闭环”。展示十公里目标、当前周计划、已确认的周一活动和跑后 Check-in。

讲解：

> 活动匹配先产生候选，只有用户确认后才成为执行事实；每次确认携带计划 revision，旧页面不能覆盖新计划。当前演示库已预置一条确认记录，方便直接展示完成状态。

## 2:40—3:30：长期偏好与上下文工程

操作：展开“长期训练偏好”，展示“周日长跑”。预览下一周计划，指出长距离课安排在周日。

讲解：

> 这不是把聊天全部塞进向量库。偏好必须显式确认，带来源、有效期和替代链；Planning Agent 只读取与规划有关的偏好，并把记忆版本写入 input hash 和 evidence。目标可训练日与偏好冲突时，目标级设置优先。

## 3:30—4:35：多 Agent 协作与人工确认

操作：点击“运行跨职责评估”。展示 Execution、Recovery、Plan 三个节点状态和待确认调整草案。

讲解：

> Coach 只负责路由。Execution 核对计划和活动，Recovery 根据确认事实与 Check-in 做保守分层，只有需要调整时才调用 Plan。每个节点只拿最小类型化 Handoff，并受工具权限、预算、超时和 Schema 约束。

停在“等待确认”状态，不立即批准。

## 4:35—5:00：可靠性收尾

操作：打开工程观测台或展示架构图。

讲解：

> Agent 只能生成草案。用户批准时，服务端会重放原请求并比较完整结果、Hash 和 revision；状态变化就标记 stale。聊天里的长期偏好也只会先形成待确认 Candidate，服务端核对原消息与 Hash 后才能写入正式 Memory。上一完整训练周还能结算为带来源、版本和失效语义的正式记忆，并按 Execution、Recovery、Plan 职责裁剪后使用；用户可在记忆档案统一审计和撤销。项目当前181项测试，单 Agent 12场景、多 Agent 18场景、Memory Manager 16场景都有版本化基线，但我不会把合成评测描述成生产效果。

## 常见现场故障与降级

| 故障 | 现场处理 |
|---|---|
| 8766端口被占用 | 增加 `--port 8770`，打开对应地址 |
| 页面残留上次状态 | 停止服务，重新执行 `demo-seed --reset` |
| 没有 DeepSeek Key | 保持增强回答关闭，使用默认离线证据回答 |
| 浏览器缓存旧静态资源 | 重启旧服务后强制刷新；当前资源版本见 `CURRENT_STATE.md` |
| Coach 未生成调整草案 | 确认使用演示数据库而非真实数据库，并检查演示 Check-in 是否存在 |
| 被追问真实用户效果 | 明确区分工程验证、个人试用和大规模用户验证，不编造结论 |

## 演示结束后的复位

停止服务即可。演示数据库可以保留，也可以在下次演示前由 `demo-seed --reset` 重建；不要把 `data/private/demo/` 提交到 Git。
